1.618 졸업작품 거래 중개

졸업작품과 신진 작가의 작품을 둘러보고, 마음에 드는 작가에게 직접 거래를 문의하는 서비스입니다.

Java · Spring Boot · JPA · MySQL

회원과 작가의 경계

학생 작가는 학교와 전공을, 사업자 작가는 사업자 정보를 등록합니다. 처음에는 두 유형에 회원 ID가 각각 있었습니다. 팀과 모델을 고치면서 회원 ID는 공통 작가 프로필로 옮기고, 등록 자격을 확인하는 정보만 유형별로 남겼습니다. 덕분에 팔로우할 때는 상대가 어느 유형의 작가인지 알 필요가 없어졌습니다.

닉네임과 활동명 리팩터링 설계안

작가를 등록할 때는 회원 닉네임을 그대로 복사했습니다. 그런데 구매자가 기억하는 이름은 전시에서 본 활동명입니다. 계정의 닉네임과 같아야 할 이유가 없었습니다.

DDD의 바운디드 컨텍스트에서 힌트를 얻어, 두 이름을 누가 정하고 어디서 쓰는지 다시 나눴습니다. 작가가 등록할 때 활동명을 직접 정하고 작품 목록과 작가 검색은 그 이름을 쓰도록 설계했습니다. 회원이 닉네임을 바꾸더라도 작품에 걸린 작가명은 그대로입니다.

KIS 주식 주문 자동화

한국투자증권에 보낸 주문과 실제 체결을 따로 기록하고, 새로 체결된 수량만 전략별 보유량에 반영합니다.

Java · Spring · JPA · 한국투자증권 Open API

같은 체결의 중복 반영 방지

3주 주문 중 첫 1주가 1,000원에 체결됐고, 다음 조회에서 누계가 2주·2,050원이 됐습니다. 이미 기록한 값을 빼면 새로 산 1주의 가격은 1,050원입니다. 보유한 두 주의 평균 단가는 1,025원입니다.

세 번째 조회에서 누계가 그대로라면 체결을 추가하지 않습니다. 주문번호와 누적 수량·금액을 묶어 어디까지 반영했는지 구분했습니다.

주문 응답이 끊긴 경우

접수 뒤 응답만 끊겼을 수 있으므로 주문을 ‘미확인’ 상태로 남기고 자동 재주문을 막았습니다.

회귀 테스트

부분 체결에서는 추가 금액과 평균 단가를 따로 검사하고, 전량 체결된 주문을 다시 조회했을 때 추가 기록이 0건인지 확인했습니다. 한 주문의 조회가 실패해도 같은 배치의 다음 주문은 처리돼야 합니다.
